## 知识库系统：需求澄清与环境实测

用户提供了一份与豆包讨论得出的《知识库系统前后端分离方案》（Vue3 + Python），要求据此制定具体开发计划，并允许提问直到完全理解需求。

### 需求澄清（4 轮问答）
1. 交付范围 → 完整可运行 MVP 代码
2. LLM 接入 → 做抽象层，本地/远程可热切换
3. 环境 → 本机 Windows 开发 + Linux 服务器部署
4. 规模 → 中大规模 1000-10000 篇
5. 模型端点 → `http://192.168.124.221:8000/v1`
6. 用户体系 → 无需登录，内网直接访问
7. 文档构成 → 先不引入 PaddleOCR
8. 部署 → 目标服务器可用 Docker
9. 响应指标 → 首字 <1.5s + 流式（放弃原"5 秒完整答案"）
10. 并发 → 1-5 人部门级
11. 文档性质 → 混合类型
12. Rerank → 先不上，RRF 融合够用
13. 交付节奏 → 分阶段，每阶段独立可验证
14. 向量库 → 用户先给了 docmind-index(8001)，后澄清**是其他项目的，不用**，需新建
15. 样本 → 用户会拷 5-10 篇真实文档到工作区

### 环境实测（详见 MEMORY.md）
实测了 LLM 速度/并发/思考模式、Embedding 契约/维度/吞吐/批量上限、Milvus 端口、本机开发环境。
关键发现：LLM 是 27B 而非原方案的 8B；无 embedding 接口；BGE-M3 自带 sparse 可省掉 ES；
docmind-index 检索 280s 超时（佐证不共用）。
