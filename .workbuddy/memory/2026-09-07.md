## 修复「运行诊断」LLM 卡片误报异常
- 现象：诊断接口返回 `llm.current.ok=true` 等全绿，但前端 LLM 卡片仍显示「异常」
- 根因（前后端契约不一致）：后端 `services/health.py:check_llm()` 返回
  `{provider, current:{ok,...}, deepseek?:{ok,...}}`，**无顶层 `llm.ok`**；
  而前端 `SettingsView.vue` 读 `d.llm.ok`（=undefined→falsy→「异常」），`types/api.ts` 的
  `ConfigDiagnostics.llm` 也误写成顶层 `ok` 结构
- 修复：`types/api.ts` 新增 `ConfigDiagnosticsLLM{provider,current,deepseek?}`，`ConfigDiagnostics.llm` 改用它；
  `SettingsView.vue` 改读 `d.llm.current.ok`（当前生效 provider），`diagDetail` 入参改可选；
  `stores/__tests__/settings.test.ts` mock/断言同步为 `llm.current.ok`
- 验证：`npm run build` 仍因 `vitest` 未安装（node_modules 缺失，预存在）在测试文件报
  `Cannot find module 'vitest'`，与本次无关；dev 服务器热更新后重跑诊断即正确
- 注：前端 `npm run dev` 不做测试类型检查，故不影响开发预览
