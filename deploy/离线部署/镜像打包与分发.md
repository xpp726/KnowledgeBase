# 知识库基础设施镜像打包与内网分发

> 本目录用于在内网/无外网环境下部署整套基础设施。
> 流程：联网机器上 `docker save` → 拷贝到内网机器 → `docker load`。

---

## 1. 涉及的全部镜像

| 镜像 | 大小 | 来源 | 备注 |
|---|---:|---|---|
| `kb-bge-m3:latest` | **10.9 GB** | 本机 `docker build` | **烘焙了 BGE-M3 完整权重**，目标机无需联网下载 |
| `milvusdb/milvus:v2.5.27` | 2.2 GB | Docker Hub | v2.5 LTS 最新 patch，支持 dense+sparse 混合检索 |
| `zilliz/attu:v2.5` | 400 MB | Docker Hub | Milvus 可视化（可选） |
| `quay.io/coreos/etcd:v3.5.5` | 182 MB | quay.io | Milvus 元数据存储依赖 |
| `minio/minio:RELEASE.2023-12-20T01-00-02Z` | 151 MB | Docker Hub | Milvus 对象存储依赖 |
| **合计（未压缩）** | **~13.8 GB** | | |

> **为什么 kb-bge-m3 这么大？** 因为镜像里 baked 了完整的 BGE-M3 权重（pytorch_model.bin 约 2.2 GB + tokenizer + 配置文件）。这是为了**目标机完全离线可用**——无需现场联网下载。如果可以联网，这一步可以省掉，但本项目定位内网使用，必须 baked。

## 2. 在联网机器上：导出镜像

### 2.1 推荐方式：gzip 压缩（节省 40~60% 传输带宽）

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\deploy\离线部署\images

# 一次性导出全部 5 个镜像为 .tar.gz
docker save kb-bge-m3:latest | gzip > kb-bge-m3.tar.gz
docker save milvusdb/milvus:v2.5.27 | gzip > milvus.tar.gz
docker save quay.io/coreos/etcd:v3.5.5 | gzip > etcd.tar.gz
docker save minio/minio:RELEASE.2023-12-20T01-00-02Z | gzip > minio.tar.gz
docker save zilliz/attu:v2.5 | gzip > attu.tar.gz
```

预期输出大小（gzip 后，参考值）：

| 文件 | 预计大小 |
|---|---:|
| `kb-bge-m3.tar.gz` | ~5.5 GB |
| `milvus.tar.gz` | ~1.1 GB |
| `attu.tar.gz` | ~150 MB |
| `etcd.tar.gz` | ~80 MB |
| `minio.tar.gz` | ~75 MB |
| **合计** | **~6.9 GB** |

### 2.2 备选方式：原始 tar（保留所有 layer 信息，可二次分发）

```powershell
docker save -o kb-bge-m3.tar kb-bge-m3:latest
docker save -o milvus.tar milvusdb/milvus:v2.5.27
docker save -o etcd.tar quay.io/coreos/etcd:v3.5.5
docker save -o minio.tar minio/minio:RELEASE.2023-12-20T01-00-02Z
docker save -o attu.tar zilliz/attu:v2.5
```

> 仅当目标机器也要做镜像分发时才选这个——原始 tar 体积大但能 1:1 还原所有 layer 元数据。

### 2.3 一键导出脚本（PowerShell）

把下面这段保存为 `导出全部镜像.ps1`，双击即可：

```powershell
$ErrorActionPreference = "Stop"
$out = $PSScriptRoot
Set-Location $out

$images = @(
    @{ name = "kb-bge-m3";        src = "kb-bge-m3:latest";                                   file = "kb-bge-m3.tar.gz" },
    @{ name = "milvus";           src = "milvusdb/milvus:v2.5.27";                            file = "milvus.tar.gz" },
    @{ name = "etcd";             src = "quay.io/coreos/etcd:v3.5.5";                         file = "etcd.tar.gz" },
    @{ name = "minio";            src = "minio/minio:RELEASE.2023-12-20T01-00-02Z";           file = "minio.tar.gz" },
    @{ name = "attu";             src = "zilliz/attu:v2.5";                                   file = "attu.tar.gz" }
)

foreach ($img in $images) {
    Write-Host "==> 导出 $($img.src) ..." -ForegroundColor Cyan
    docker save $img.src | gzip > $img.file
    $size = (Get-Item $img.file).Length / 1GB
    Write-Host "    完成: $($img.file) ($([math]::Round($size, 2)) GB)" -ForegroundColor Green
}

Write-Host "`n全部完成。文件列表:" -ForegroundColor Green
Get-ChildItem *.tar.gz | Format-Table Name, @{n="GB";e={[math]::Round($_.Length/1GB, 2)}}
```

## 3. 拷贝到内网机器

任选一种：

| 方式 | 命令 | 适用 |
|---|---|---|
| U 盘 / 移动硬盘 | 直接拷贝 `images\` 整个目录 | 单台机器部署 |
| scp | `scp images/*.tar.gz user@内网:/path/to/images/` | Linux 服务器 |
| 内网文件共享 | 拷贝到 `\\内网服务器\共享目录\kb-images\` | 公司有文件服务器 |
| WinSCP / MobaXterm | 图形化拖拽 | Windows 内网服务器 |

## 4. 在内网机器上：加载镜像

### 4.1 逐个加载

```bash
cd /path/to/images
gunzip -c kb-bge-m3.tar.gz | docker load
gunzip -c milvus.tar.gz   | docker load
gunzip -c etcd.tar.gz     | docker load
gunzip -c minio.tar.gz    | docker load
gunzip -c attu.tar.gz     | docker load
```

### 4.2 一键加载脚本（bash）

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")"
for f in *.tar.gz; do
    echo "==> 加载 $f ..."
    gunzip -c "$f" | docker load
done
docker images | grep -E "kb-bge-m3|milvus|attu|coreos/etcd|minio/minio"
```

### 4.3 验证

```bash
docker images | grep -E "kb-bge-m3|milvus|attu|coreos/etcd|minio/minio"
```

应看到 5 个镜像齐全，标签正确。

## 5. 后续启动

加载完成后，内网机器的操作与外网一致：

```bash
cd <项目 deploy 目录>
# 需要可视化界面（attu）才加 --profile tools，否则去掉该参数
docker compose --profile tools up -d
```

> ⚠️ 目标机前提条件：
> - Docker 20.10+（推荐 Docker Desktop 或 docker-ce 最新版）
> - kb-bge-m3 服务的 `deploy.resources.reservations.devices` 段要求 **NVIDIA Container Toolkit**（GPU 透传）
> - 镜像架构必须匹配（x86_64 ↔ x86_64；ARM 镜像要重新构建 kb-bge-m3）

## 6. 故障排查

| 现象 | 排查 |
|---|---|
| `docker load` 后 `docker images` 看不到镜像 | 确认 gzip 流是完整管道：`gunzip -c xxx.tar.gz \| docker load`，不要拆成两步先解压再 load |
| `kb-bge-m3` 容器报 `cuda runtime error` | 目标机没装 NVIDIA 驱动 / Container Toolkit，需要安装 |
| MinIO / Milvus 容器起不来 | 检查命名卷权限：`docker volume inspect deploy_minio-data --format '{{.Mountpoint}}'`，确保 WSL2 / Docker 守护进程对目录有 rwx |
| 想跳过 attu 减小镜像集 | 不复制 `attu.tar.gz` 即可，deploy 时去掉 `--profile tools` |

## 7. 更新镜像后如何重新打包

只需对**变化过的**镜像重新打包：

```powershell
# 改了 deploy/embed/server.py → 重建并只重新打 kb-bge-m3
cd E:\SQS\Projects\Xpp\KnowledgeBase\deploy\embed
docker build -t kb-bge-m3:latest .   # 缓存命中前面所有层，秒级

cd ..\离线部署\images
docker save kb-bge-m3:latest | gzip > kb-bge-m3.tar.gz
```

只把这一个文件传到内网加载即可，其他 4 个镜像没动就不必重复。
