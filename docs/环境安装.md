# 前后端开发环境安装文档

> 适用范围：Windows 本机单机开发（单人）。
> 前置已完成：Git、Docker Desktop、Node.js（见「0. 前置依赖一览」）。
> 本文档只覆盖**前后端运行时**的搭建：Python 虚拟环境 → 依赖安装 → 启动与验证。

---

## 0. 前置依赖一览（假设已安装）

| 依赖 | 要求 | 本机验证命令 |
| :--- | :--- | :--- |
| Git | 任意新版本 | `git --version` |
| Node.js | **22.x**（前端用 npm） | `node -v` → 应显示 `v22.x` |
| npm | 随 Node 自带 | `npm -v` |
| Docker Desktop | 含 docker-compose v2 | `docker --version` / `docker-compose --version` |
| Python | **3.11+**（已验证 3.13.14 可用） | `python --version` |

> 若 `python` 指向 Python 2，用 `python3` 替代下文所有 `python`。
> Windows 上若 `python` 命令不存在，从 Microsoft Store 或 python.org 安装并勾选「Add to PATH」。

## 一、后端环境（FastAPI）

后端代码位于 `backend/`。依赖见 `backend/requirements.txt`。

### 1.1 创建并激活虚拟环境

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\backend

# 创建虚拟环境（只需一次）
python -m venv .venv

# 激活（每次开新终端都要执行）
.venv\Scripts\activate
```

激活后命令行前缀会出现 `(.venv)`，表示已进入虚拟环境。

### 1.2 安装依赖

```powershell
# 确保已激活虚拟环境，再升级 pip 并安装
python -m pip install --upgrade pip
pip install -r requirements.txt
```

⚠️ **Windows 编译坑（大概率遇到）**

`requirements.txt` 里的 `asyncmy`（MySQL 异步驱动，开发期用 SQLite 时不实际用到）是 C 扩展，
在本机没有 C 编译器时会**编译失败导致整个 `pip install` 中断**。

两种解法（任选其一）：

- **方案 A（推荐，开发期够用）**：临时注释掉 `requirements.txt` 里 `asyncmy` 那一行，再 `pip install`。
  生产部署用 MySQL 时再装（部署机通常有编译环境或预编译 wheel）。
- **方案 B**：安装 Visual Studio 生成工具（勾选「使用 C++ 的桌面开发」工作负载），再重跑 `pip install`。
  下载：https://visualstudio.microsoft.com/zh-hans/visual-cpp-build-tools/

> 其他包（pymupdf4llm / lxml / cryptography 等）在 Windows 上均有预编译 wheel，通常一次装好。
> 若某个包卡在「Building wheel」超过几分钟，基本就是缺编译器，回到上面方案处理。

### 1.3 配置 .env

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\backend
copy .env.example .env
```

用编辑器打开 `backend/.env`，**开发期只需填一项**（其余保持默认）：

```ini
# 开发期 LLM 用 DeepSeek 公网 API，必须填 key 才能问答
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-你的真实key
```

> 其他默认值已配好：
> - 数据库 `DATABASE_URL=` 留空 → 自动用 `data/kb.db`（SQLite + aiosqlite），无需额外配置
> - Embedding `EMBED_BASE_URL=http://localhost:8003`（本机 Docker 的 BGE-M3）
> - Milvus `MILVUS_HOST=localhost` / `19530`（本机 Docker）
> - 文件存储 `STORAGE_BACKEND=local`（写 `data/uploads`）

### 1.4 启动后端

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\backend

# 开发模式（热重载，改动代码自动重启）
python -m app.run --reload
```

- 默认监听 `http://0.0.0.0:8000`
- 交互式 API 文档：`http://localhost:8000/docs`
- 日志落在 `backend/data/logs/{app,access}.log`（由 `.env` 的 `LOG_DIR` 控制）

> 注意：必须经由 `python -m app.run` 启动（不要直接 `uvicorn app.main:app`），
> 否则日志配置不会生效，只输出到控制台。详见 `backend/app/run.py` 顶部注释。

## 二、前端环境（Vue 3 + Vite）

前端代码位于 `frontend/`，依赖见 `frontend/package.json`，包管理器用 **npm**。

### 2.1 安装依赖

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\frontend
npm install
```

> `node_modules/` 通常已存在，重跑 `npm install` 是幂等的，可安全重复执行。
> 若 `package-lock.json` 与 `node_modules` 不一致导致报错，先 `npm ci` 再 `npm install`。

### 2.2 启动开发服务器

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\frontend
npm run dev
```

- 默认监听 `http://localhost:5173`
- Vite 已配置代理：`/api` → `http://127.0.0.1:8000`（即后端地址），前端无需关心跨域
- 浏览器打开 `http://localhost:5173` 即为开发界面

### 2.3 构建生产包（可选，部署用）

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\frontend
npm run build
```

产物在 `frontend/dist/`，可由 Nginx 等静态服务器托管。

## 三、端到端验证

### 3.1 前置：基础设施（Docker）需先启动

后端会连接本机 Docker 里的 Milvus 与 BGE-M3 Embedding。若它们没起，后端 `/api/health` 会报连接失败。

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\deploy
docker-compose --profile tools up -d
docker-compose ps        # 确认 milvus / bge-m3 / etcd / minio 均为 Up (healthy)
```

### 3.2 验证后端

```powershell
# 健康检查（应返回 embedding / milvus / llm 三项的 status）
curl http://localhost:8000/api/health
```

浏览器打开 `http://localhost:8000/docs` 能看到 Swagger 界面即后端 OK。

### 3.3 验证前端

浏览器打开 `http://localhost:5173`，能加载页面即前端 OK。
在页面里发起一次问答，请求走 `/api` 代理到后端 8000，再到 LLM / Milvus / BGE-M3。

## 四、常见问题

**Q1：后端启动报 `ModuleNotFoundError`**
→ 虚拟环境没激活，或装包时因 asyncmy 编译失败中断导致部分包没装上。
回到 1.2 节按方案 A/B 处理，确保 `pip install -r requirements.txt` 无报错结束。

**Q2：前端 `npm run dev` 后页面空白 / 接口 404**
→ 确认后端已在 8000 运行，且 Vite 代理目标 `http://127.0.0.1:8000` 可达。
后端没起时，`/api/*` 请求会 404。

**Q3：`pip install` 卡在 Building wheel 很久**
→ 基本是缺 C 编译器（见 1.2 节 Windows 编译坑）。不要干等，按方案处理。

**Q4：问答时 LLM 报 401 / 无响应**
→ `.env` 里 `DEEPSEEK_API_KEY` 没填或填错；或 `LLM_PROVIDER` 不是 `deepseek`。
改完 `.env` 需重启后端。

**Q5：后端连不上 Milvus / Embedding**
→ 基础设施 Docker 没起（见 3.1 节），或 `deploy/` 那套服务没 `up -d`。
确认 `docker-compose ps` 里 `bge-m3` 和 `milvus` 都是 healthy。
