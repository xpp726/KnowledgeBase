## 1. 分层依赖方向

```
HTTP / SSE 请求
      ↓
① api/ 层        路由 · 参数校验 · SSE 协议 · 错误映射（不写业务，不直连 db）
      ↓
② services/ 层   业务编排（ingestion / retrieval / rag / document / conversation / tasks）
      ↓
③ 数据访问 + 外部客户端
   models(SQLAlchemy ORM) · embedding · vectorstore · llm · storage 实现
      ↓
MySQL（阶段5）/ SQLite（开发） · Milvus（kb_id 过滤） · MinIO · BGE-M3 · LLM
```

约束：
- api 不直连 db / 外部服务；services 不 import FastAPI；外部客户端只做协议转换、不含业务规则。
- services 之间可互相调用。

## 3. 分层职责

| 层 | 职责 | 禁止 |
|---|---|---|
| api/ | 参数校验、SSE 协议、错误→状态码 | 写业务逻辑、直连 db |
| services/ | 业务编排（入库/检索/RAG/文档/会话） | import FastAPI、碰 HTTP |
| models/ | ORM 模型、表结构、会话管理 | 业务规则 |
| 外部客户端 | 协议转换（embedding/vectorstore/llm/storage） | 业务规则 |
| scripts/ | CLI 入口，复用 services | 复制业务逻辑 |

## 4. 数据模型变更

| 表 | 现状 | 变更 |
|---|---|---|
| knowledge_bases | 无 | 新增：kb_id PK, name, description, created_at |
| documents | 无 kb 维度 | + kb_id（FK）；file_path 语义改为对象存储 key；status 状态机扩展 |
| chunks | 5 字段 | + kb_id（与 Milvus 行对齐） |
| conversations | 无 kb 维度 | + kb_id（会话挂知识库） |
| messages | 有 refs_json | 不变（kb_id 走会话关联） |
| query_logs | 有统计字段 | + kb_id |
| 二期 | — | users / 权限表（user_id 届时补，本期不加） |

**documents.status 状态机**：pending → ingesting → embedding → done；失败 → failed（带 error）；启动扫描 stuck（超时阈值）→ 标记 failed 或重跑。

**删除补偿**：删文档 = ① Milvus 向量 → ② MinIO 文件 → ③ DB 记录；每步成功才进下一步，失败写补偿日志，scripts/cleanup.py 兜底。

**日志持久化**：日志统一落盘 `data/logs/`（LOG_DIR 可覆盖，相对路径以 backend 根解析）。`app/log_config.py` 用 dictConfig 构建双输出：console（开发期实时观察）+ 文件（按天轮转，保留 LOG_RETENTION_DAYS 天）；业务日志与 HTTP 访问日志分离为 `app.log` / `access.log`（避免两个 handler 写同一文件在轮转时竞争）；第三方库（sqlalchemy/httpx/urllib3/pymilvus）默认 WARNING 降噪，排障时调 LOG_LEVEL=DEBUG。业务代码全程 `logging.getLogger(__name__)`，经 root 自动落文件，无需改动业务代码。**必须经 `python -m app.run` 启动**（run.py 注入日志配置），裸 `uvicorn app.main:app` 会被 uvicorn 默认配置覆盖、只输出到控制台。

## 5. 抽象决策表

| 抽象点 | 决策 | 依据 |
|---|---|---|
| LLM provider | ✅ 抽象（保留 builder 模式） | 多真实 provider |
| Embedding | ❌ 不抽象 | 单一实现 |
| 向量库 | ❌ 不抽象（保持封装） | 单一实现 |
| FileStorage | ✅ 抽象（Local + MinIO） | 开发/部署环境不同 |
| 任务执行器 | ❌ 不抽象（asyncio + 状态机） | 单进程 |
| OCR / rerank | 目录占位 | 二期 |
| 数据访问 | SQLAlchemy ORM（不另做 repository） | Q1 选型 |
