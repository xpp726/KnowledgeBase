# 新机器（家里）部署手册：拉取远程代码 + SQLite 切 MySQL + 清理向量库残余

> 适用场景：家里电脑已有旧代码（本地整改、SQLite 数据库），现在要**丢弃本地代码**、
> **直接拉取远程 master**，并改用**全新 MySQL 数据库**，同时**清理 Milvus 向量库中的残余数据**。
> 本手册同样适用于任何一台新机器从零部署。

---

## 0. 部署前整体认知

| 项 | 家里旧环境（丢弃） | 新环境（本手册目标） |
|---|---|---|
| 代码 | 本地整改，全部丢弃 | 远程 `origin/master`（公司最新代码） |
| 数据库 | SQLite（`backend/data/kb.db`） | MySQL（Docker 容器 `127.0.0.1:13306/kb`，全新空库） |
| 向量库 | Milvus 有旧代码写入的残余向量 | drop 原 collection 重建（`scripts/init_collection.py`） |
| 对象存储 | MinIO 可能有孤儿文件 | 可选清理（`scripts/cleanup.py --purge-orphans`） |
| 默认管理员 | — | 后端启动自动创建 `admin / admin` |

**为什么向量库必须清理**：旧代码曾向 Milvus 的 `kb_chunks` collection 写入向量数据，
新代码的向量 schema / 字段可能与旧数据不一致。不清理会导致检索报错或返回脏数据。
最干净的做法是删除整个 collection 按新 schema 重建（下面第 5 步）。

## 1. 前置依赖（假设本机已安装）

| 依赖 | 版本要求 | 用途 |
|---|---|---|
| Git | 任意较新版本 | 拉取代码 |
| Docker Desktop | 需支持 Linux 容器 | 跑 MySQL / Milvus / MinIO / BGE-M3 基础设施 |
| Python | **3.13**（含 pip） | 后端（onnxruntime 1.29 需独立 Python 3.13） |
| Node.js | 18+ | 前端构建与开发 |
| NVIDIA GPU + 驱动 | 有 GPU 更佳 | BGE-M3 向量化服务（compose 里申请了 GPU） |

> 无 GPU 时 bge-m3 容器可能起不来，可去掉 `deploy/docker-compose.yml` 中
> `bge-m3` 服务的 `deploy.reservations` 段改用 CPU 推理（速度慢），或按需调整。

## 3. 拉取最新代码（丢弃本地旧代码）

> ⚠️ 以下操作会**丢弃家里电脑上所有本地改动和本地提交**，请先确认旧代码不再需要。
> 如需留底，先把整个目录复制一份到别处再执行。

方式一：在当前目录重置（推荐，保留 .git 历史）

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase
git fetch origin
git reset --hard origin/master
# 清掉未跟踪的旧文件（旧 .env、旧 data 目录等，执行前确认无需要保留的文件）
git clean -fd
```

方式二：全新克隆（最干净，旧目录直接改名留底）

```powershell
# 先把旧目录改名为 KnowledgeBase_old 留底，然后：
git clone git@github.com:xpp726/KnowledgeBase.git
```

拉取后确认版本：

```powershell
git log --oneline -3
```

应看到远程最新提交（含"文件预览/下载"与"日志配置"等提交）。

> 旧 SQLite 数据文件（如 `backend/data/kb.db`）不再需要，随 `git clean -fd` 或目录改名一并处理。

## 4. 配置后端环境（关键：切 MySQL）

### 4.1 创建虚拟环境并安装依赖

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

> ⚠️ `asyncmy` 连 MySQL 9.x 依赖 `cryptography` 包（已在 requirements.txt），
> 若 pip 安装失败请确认 Python 版本为 3.13 且网络可访问 PyPI。

### 4.2 配置 .env

```powershell
Copy-Item .env.example .env
```

编辑 `backend\.env`，以下为**必须修改**的项（其余保持模板默认）：

```ini
# ===== 数据库：从 SQLite 切到 MySQL（本手册核心变更） =====
DATABASE_URL=mysql+asyncmy://kb:kb_user_pwd_change_me@127.0.0.1:13306/kb
DB_ECHO=false

# ===== LLM（家里一般用 DeepSeek 公网 API） =====
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-你的key
DEEPSEEK_MODEL=deepseek-chat

# ===== Embedding（本机 Docker 自建 BGE-M3） =====
EMBED_BASE_URL=http://localhost:8003
EMBED_MODEL=BAAI/bge-m3
EMBED_DIM=1024

# ===== Milvus（本机 Docker） =====
MILVUS_HOST=localhost
MILVUS_PORT=19530
MILVUS_COLLECTION=kb_chunks

# ===== 文件存储（MinIO，部署模式） =====
STORAGE_BACKEND=minio
MINIO_ENDPOINT=localhost:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=minioadmin
MINIO_BUCKET=kb-files
MINIO_SECURE=false

# ===== 日志 =====
LOG_DIR=data/logs
LOG_LEVEL=INFO
```

> - `DATABASE_URL` 留空 = 回到 SQLite（仅开发自用，本手册目标是用 MySQL）
> - 后端启动时会**自动建表**（新表）并**幂等补齐缺失列**，全新 MySQL 空库无需手动建表
> - 内网可访问 vLLM 时，把 `LLM_PROVIDER=qwen` 并按模板填 `LLM_BASE_URL`

## 5. 清理向量库残余（重点步骤）

在 `backend` 目录、虚拟环境已激活的状态下执行：

```powershell
cd E:\SQS\Projects\Xpp\KnowledgeBase\backend
.\.venv\Scripts\Activate.ps1
python scripts/init_collection.py
```

该脚本会：

1. **删除 Milvus 中已存在的 `kb_chunks` collection**（不存在则跳过删除）
2. 按新代码 schema 重建 collection（dense HNSW + sparse inverted 双索引）
3. 写入 3 条自检文本 → 执行 dense / sparse / 混合检索验证

看到末尾 `[OK] 向量库自检通过` 即清理 + 重建成功。

**可选：精确清理孤儿数据**（对账 DB ↔ Milvus ↔ MinIO）

```powershell
python scripts/cleanup.py              # 先只读对账，看孤儿清单
python scripts/cleanup.py --purge-orphans   # 确认后清理“向量有/DB无”与“文件有/DB无”的孤儿
```

> 全新 MySQL 空库 + 旧 MinIO 残留时，`--purge-orphans` 会清掉所有孤儿文件/向量；
> 执行前先跑一次无参对账，确认清单无误。

## 9. 常见问题

**Q1：`asyncmy` 连接 MySQL 报 `caching_sha2_password` 相关错误**
→ `cryptography` 包未安装或版本过旧，执行 `pip install "cryptography>=42.0.0"`。

**Q2：后端启动报 `no such table: xxx` / 列不存在**
→ 确认 `DATABASE_URL` 指向的是**全新空库**（或已由启动自动建表）；
   若指向旧库，删掉旧库重建，或改跑 Alembic `alembic upgrade head`（本场景不需要）。

**Q3：Milvus 检索报 schema 不匹配 / collection 异常**
→ 重跑第 5 步 `python scripts/init_collection.py` 强制 drop 重建。

**Q4：bge-m3 容器起不来**
→ 无 GPU 时去掉 compose 中 `bge-m3` 的 `deploy.reservations` 段；
   或检查 `docker compose logs bge-m3`，确认 HF_HUB_OFFLINE 生效（镜像内已烘焙权重）。

**Q5：13306 端口被占用**
→ 本机已有 MySQL 占 3306/13306 时，修改 `deploy/docker-compose.yml` 中 mysql 的端口映射，
   并同步修改 `backend/.env` 的 `DATABASE_URL`。

**Q6：MinIO 上传报 bucket 不存在**
→ 无需手动创建：后端启动时会自动 `make_bucket('kb-files')`；确认 `MINIO_ENDPOINT/ACCESS_KEY/SECRET_KEY` 与 compose 一致。

**Q7：登录失败 / 没有管理员**
→ 全新库首次启动会自动创建 `admin/admin`；若已存在旧 users 表且无管理员，
   手动在 MySQL 执行 `INSERT` 或删除 users 表后重启后端重新生成。
