### 二、问题修复

#### 1. 语音识别文本尾部拼接（"今天天气真不错。错"）
- **现象**：识别结束输入框显示 `今天天气真不错。错`，ASR 后端结果却是 `今天天气真不错。`；
- **根因**：服务端 stop 收尾 flush 时 streaming 对尾音残留输出一条 `partial`（"错"），前端把 `final` 之后的 partial 也拼入结果；后端落库只取 `sentences`（finals）故结果干净；
- **修复**（`useVoiceInput.ts`）：`stop` 消息发出后忽略之后到达的 `partial`，`final` 仍保留（手动停时尾句靠收尾 final 闭合）。

#### 2. 静音 5s 自动停止不触发
- **现象**：点击开始后一直不说话不自动停止；只有"停止说话 5s"才偶尔触发；
- **根因**：单帧静音阈值 `SILENT_RMS=0.02` 低于环境底噪（实测底噪 RMS×4 在 0.02~0.07 间波动），严格连续静音计时被尖峰反复清零；
- **修复**（`useVoiceInput.ts`）：阈值提升至 **0.05**；判定改为 **最近 5s 滑动窗口内静音帧占比 ≥80%**（容忍底噪尖峰），窗口不足 4.8s 不判定（避免短录音误停）。

#### 3. 会话历史消息顺序颠倒（先答后问）
- **现象**：历史会话恢复后同一轮的"答"显示在"问"之前；
- **根因**：历史数据中 user/assistant 消息 `created_at` 相同（同整数秒），`list_messages` 仅按 `created_at` 单键排序，同值顺序不稳；
- **修复**（`backend/app/models/queries.py` `list_messages`）：排序加二级键 —— 同时间戳内 **user 消息强制在 assistant 前**（再按 id 兜底保证稳定）；`limit` 路径（多轮上下文）同步处理。

#### 4. 时间戳列 FLOAT → DOUBLE（根因修复）
- **现象**：全库所有 `created_at`/`updated_at` 均为整数（`.0`），且 user/assistant 消息时间戳几乎必然相同；
- **根因**：SQLAlchemy 将 `Mapped[float]` 默认映射为 MySQL **FLOAT（单精度，约 7 位有效数字）**。在 17 亿级时间戳下 FLOAT 分辨率仅约 ±128s，user/assistant 写入时间差（几秒~几十秒）会被舍入成**同一值** —— 这才是消息顺序不稳、以及"user/assistant 共用时间"的**数据层根因**；
- **修复**：`backend/app/models/base.py` 在 `Base.type_annotation_map` 注册 `float -> Double`（双精度，微秒级，全局覆盖 7 个模型）；`ALTER TABLE` 将 kb 库 13 个时间戳列由 FLOAT 改为 DOUBLE（无损迁移）；
- **验证**：事务内写入 user/assistant 两条消息，时间戳分别为 `1789230861.1941156` / `1789230861.2648547`（差 0.07s 精确保留），回滚未落库。

#### 5. 时间戳全链路统一 DATETIME（2026-09-13，规范统一）
- **背景**：FLOAT→DOUBLE 修复了精度，但秒浮点仍是"非标"存储；与 ASR 项目（本就 DATETIME）统一，用户拍板追求规范统一，全链路改为 MySQL **DATETIME**（本地时间 naive，与 `datetime.now()` 语义一致）。
- **模型层**（`backend/app/models/`）：`base.py` `TimestampMixin` 及 conversation/chunk/log/user 全部 `Mapped[datetime]` + `DateTime`，`default=datetime.now` / `onupdate=datetime.now`；`Base.type_annotation_map` 移除 `float -> Double` 注册（仅保留 `str -> String(255)`），避免后续误映射；
- **写入层**：`queries.py` 全部 `time.time()` → `datetime.now()`（folder/conv `updated_at`、`add_message` 默认值等）；`auth.py` `last_login_at = datetime.now()`；`document_service.py` `recover_stuck` 的 `before = datetime.now() - timedelta(seconds=timeout)`；
- **查询/统计层**：`stats_summary` 的 `since` 改 `datetime.combine(start_date, datetime.min.time())`、按天聚合改 `r.created_at.date().isoformat()`；
- **API 契约**：`schemas.py` 9 处 `: float` → `: datetime`，Pydantic 自动序列化为 **ISO 字符串**（如 `2026-09-12T16:17:04`）；
- **数据迁移**：MySQL kb 库 **14 个时间戳列**（chunks/conversations/documents/folders/knowledge_bases/messages/query_logs/users）DOUBLE 秒浮点 → DATETIME；迁移用 `datetime.fromtimestamp(sec)`（Python 本地时区，与未来写入语义一致）；`<=0` 值（如 `last_login_at=0` 从未登录）转 NULL；
- **前端契约**：`api.ts` 时间字段 `number` → `string`（ISO）；`chat.ts` `createdAt: Date.parse(m.created_at)`、新会话 `new Date().toISOString()`；`DocumentsView/UsersView` `formatTime(ts: string | number)` 兼容两种形态；
- **验证**：后端 pytest **173 passed**（测试库 `test_kb.db` 旧 schema 已删除重建）；前端 vitest 66 passed、vue-tsc/`npm run build` 通过；真实 API 返回 `"created_at":"2026-09-12T16:17:04"`。

#### 6. 清理 SQLite，全链路仅 MySQL（2026-09-13）
- **背景**：项目早期用 SQLite 过渡，`db.py` 长期保留 legacy 裸 sqlite3 层；用户明确后续不再使用 SQLite，全面清理。
- **生产代码**：
  - `app/db.py`：删除 legacy 同步层（`SCHEMA`/`_connect`/`get_conn`/`init_db`/`upsert_document`/`get_document`/`list_documents`/`delete_document`/`replace_chunks`/`get_chunks`/`stats`/`new_id`），只保留 SQLAlchemy 2.0 async 层；`ensure_schema_patches`/`_column_exists` 只留 MySQL（information_schema 检测）。
  - `app/config.py`：删除 `sqlite_path`；`resolved_database_url` 不再提供 SQLite 兜底，`DATABASE_URL` 未配置直接报错。
  - `app/services/config_service.py`：系统设置 database 字段恒 mysql；`app/services/health.py`：删 SQLite 方言分支。
  - `requirements.txt`：移除 `aiosqlite`；`.env.example`、`环境安装.md`、`新环境部署手册.md` 同步更新。
  - `scripts/eval_retrieval.py`：`db.stats()`（legacy SQLite 统计）改为 ORM 异步统计 `db_stats()`（MySQL CHAR_LENGTH）。
- **测试基建（SQLite 临时库 → 共享 MySQL kb_test）**：
  - conftest：测试库改为 **MySQL kb_test**（docker kb-mysql 容器）；用 **NullPool** 替换 `app.db` 的 engine/AsyncSessionLocal，规避 asyncmy 在 TestClient（anyio portal 独立循环）与 pytest-asyncio 循环间复用连接池的 `AttributeError: 'NoneType' object has no attribute 'send'`；
  - 每用例开始前清空全部业务表并 ensure 默认 admin（TestClient 登录依赖），结束后再清一次，模拟 SQLite 独立库隔离；
  - 7 个测试文件：`create_async_engine(sqlite tmp_path)` 全部改为共享 `app.db.async_engine`，删除逐文件建表/dispose；`test_auth::test_list_users` 断言改为超集（共享库含系统 admin）。
- **遗留数据**：`backend/data/kb.db`（旧开发库）与 `test_kb.db`（旧测试库）已删除。
- **验证**：后端 pytest **173 passed**（MySQL kb_test 全绿）；后端重启后健康检查 `mysql` dialect 正常，`DATABASE_URL` 未配置时会显式报错提示。
